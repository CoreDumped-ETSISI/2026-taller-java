## 9. Clases Abstractas e Interfaces

En la programación orientada a objetos (POO), tanto las **clases abstractas** como las **interfaces** son mecanismos que permiten definir contratos y lograr el polimorfismo. Sin embargo, tienen propósitos y reglas de diseño diferentes.

---

## 9.1 Clases Abstractas (`abstract class`)

Una clase abstracta es una clase que **no se puede instanciar directamente**. Su objetivo principal es servir como una **plantilla o base** para otras clases hijas (subclases).

### Características principales:
* Se declaran con la palabra reservada `abstract`.
* Pueden contener **métodos abstractos** (sin cuerpo, terminados en punto y coma) que obligatoriamente deben implementar las clases hijas.
* Pueden contener **métodos concretos** (con código implementado) que las hijas heredan directamente.
* Pueden tener atributos de cualquier tipo, constructores y métodos estáticos.

### Ejemplo práctico:

```java
// Clase abstracta
public abstract class Vehiculo {
    protected String marca;

    // Constructor
    public Vehiculo(String marca) {
        this.marca = marca;
    }

    // Método concreto (compartido)
    public void arrancar() {
        System.out.println("El vehículo " + marca + " está encendiendo el motor...");
    }

    // Método abstracto (obligatorio de implementar por las hijas)
    public abstract void acelerar();
}

// Clase concreta que extiende de la abstracta
public class Coche extends Vehiculo {
    
    public Coche(String marca) {
        super(marca);
    }

    @Override
    public void acelerar() {
        System.out.println("El coche " + marca + " acelera pisando el acelerador.");
    }
}
```

## 9.2 Interfaces (`interface`)

Una interfaz es un **contrato de comportamiento**. Define *qué* debe hacer una clase, pero no *cómo* debe hacerlo. Representa una capacidad o rol que una clase puede adoptar.

### Características principales:
* Se declaran con la palabra reservada `interface`.
* Todos sus métodos son, por defecto, `public abstract` (a partir de Java 8 se permiten métodos `default` y `static` con implementación).
* Todos sus atributos son, por defecto, `public static final` (constantes).
* Una clase **puede implementar múltiples interfaces**, solucionando la limitación de Java de no permitir herencia múltiple de clases.

### Ejemplo práctico:

```java
// Definición de la interfaz
public interface Conducible {
    void conducir(); // public abstract implícito
    
    default void tocarClaxon() {
        System.out.println("¡Beep, beep!");
    }
}

// Clase que implementa la interfaz
public class Bicicleta implements Conducible {
    @Override
    public void conducir() {
        System.out.println("Pedaleando la bicicleta por el carril bici.");
    }
}
```

## 9.3 Diferencias Clave (Tabla Comparativa)

| Característica | Clase Abstracta | Interfaz |
| :--- | :--- | :--- |
| **Herencia** | Una clase solo puede extender **una** clase abstracta (`extends`). | Una clase puede implementar **múltiples** interfaces (`implements`). |
| **Métodos** | Puede tener métodos abstractos y con implementación (concretos). | Principalmente métodos abstractos (y `default`/`static` desde Java 8+). |
| **Atributos** | Puede tener variables de instancia de cualquier tipo (privadas, protegidas, etc.). | Solo constantes públicas (`public static final`). |
| **Constructores** | **Sí** tiene constructores (útiles para inicializar estados heredados). | **No** tiene constructores. |
| **Propósito** | Relación de parentesco estricta ("es un" tipo de). | Definición de capacidades o comportamientos transversales ("puede hacer"). |

---

## 9.4 ¿Cuándo usar cada una? (Regla de oro para el taller)

> **Usa una clase abstracta cuando:**
> * Compartas código común (atributos y métodos con estado) entre clases estrechamente relacionadas.
> * Necesites usar constructores o mantener un estado interno (variables de instancia no constantes).
> 
> **Usa una interfaz cuando:**
> * Quieras definir un comportamiento común para clases que no están relacionadas jerárquicamente (ej. `Imprimible`, `Serializable`, `Comparable`).
> * Necesites simular **herencia múltiple** permitiendo que una clase cumpla varios contratos.
